# whereareyou — four-role review & aligned plan

_22 July 2026. Commissioned as: senior tech-lead review, a marketer's take, a
tester's plan, and a CEO's next-steps — plus "how does it pay for itself".
Everything below is either **measured** (live API, browser, or a script that's
committed to the scratchpad) or **flagged as opinion**. POC is explicitly
throwaway; nothing here is precious._

---

## 0. What was actually verified (the empirical spine)

Everything the four roles argue from. Measured today against the live
deployment and the three repos, not read off comments.

### Works, confirmed
- **Full session lifecycle on the live API** (`whereareyou-api.onrender.com`):
  mint → resolve (Bearer key) → PATCH live-update (mode-enforced: static→409) →
  revoke→404. Wrong `updateToken`→**404 not 403** (no oracle — verified). Bad
  checksum→400 `bad-checksum`. `ttlSeconds` honoured.
- **Structural expiry is real.** Redis native TTL, no sweeper in the code, a
  source-scanning test enforces "no sweeper", `noeviction` keeps keys from early
  drop. `/health` reports `structuralExpiry:true`.
- **Miss-priced rate limiting is real and works in apikey mode.** A failed
  lookup costs ~30× a hit; 5 misses → 429 with exponential backoff. The **key
  axis holds even under IP spoofing** (measured): per-key enumeration is
  infeasible (~7.5 years/key at 10k live sessions).
- **Voice-form input parses end to end** (browser): typing the *fully spoken*
  form "Four Yankee Eight Echo Three Tango Yankee Seven" resolved to `4Y8E-3TY7`,
  rendered the third-party banner, mapped the location, showed the note and a
  live expiry countdown. The core demo genuinely works.
- **Single-character substitution: 0 / 4,960,000 undetected = 100% caught.** The
  headline "provably impossible for a one-symbol mistype to pass" is **true**.
- **Offline-code confusability — the what3words failure mode — is measurably
  absent.** 40,000 codes in a ~950×600m block, zero pairs within Hamming
  distance 2; neighbouring 5m cells share 0–1 of 10 characters. Decode error
  ≤3.36m over 200k random points. This is the strongest part of the concept and
  it stands up.

### Broken or overstated, confirmed
- **Chunk-swap defeats the checksum ~50% of the time** (49.86%, 149,576/300,000,
  my own run). The app *displays* codes as `4Y8E-3TY7`; a dispatcher who
  transcribes the blocks in the wrong order gets a valid-checksum code half the
  time — a confident wrong pin, no "read it again". The one error the UI's own
  format invites is the one the checksum barely catches.
- **Twin errors (KK misheard/typed as CC): 19% undetected.** Non-adjacent
  transpositions: 10–30%. The "every single-character error" guarantee is
  genuinely total; the framing invites belief in a general transcription
  robustness the scheme does not have.
- **The phonetic parser rejects what a UK caller actually says.** "zed" for Z,
  "oh" for 0, "x ray" split by a speech-to-text engine, hyphen-joined words — all
  fail (closed, so no wrong location, but each is a rejected honest read-back =
  re-ask on a live 999 call). Cause: any unrecognised word silently degrades to a
  character run.
- **Live tracking is a label, not a mechanism.** `Share.tsx` fires PATCH updates
  with `void updatePosition(...)` — every failure (timeout, 404, 429, network
  death) is discarded; the `watchPosition` error callback is literally
  `undefined`; connectivity is promote-once-never-demote; the dispatcher console
  resolves **once and never re-polls**. The banner says "being shared live" with
  zero evidence it still is. For the product's stated purpose this is the single
  worst defect.
- **`TRUST_PROXY=true` makes `request.ip` attacker-controlled** (proven live: an
  `X-Forwarded-For` header set the logged IP). Turns the per-IP mint limiter into
  decoration.
- **Unauthenticated, effectively-unlimited mint** into a 25 MB `noeviction`
  free-tier Redis = ~8-minute total-outage DoS that *also* fails the rate limiter
  open. Coupled failure.
- **The log redaction is inert** — it targets request/response bodies that
  Fastify never logs, so it has never had any effect; the README still claims it
  works. What *does* leak to logs is the session **code** in plaintext, which
  outlives the session TTL in Render's log retention (a partial location history —
  exactly what the pitch says doesn't exist).
- **Session state lives only in React memory.** The service worker's own
  auto-update reload — or any accidental reload / iOS tab eviction — destroys the
  caller's code and `updateToken` mid-emergency; the session can then never be
  revoked or re-displayed.
- **The Trafalgar Square manual-pin default** is minted as a confident real
  position ("Placed by hand, sharer estimated ±12m") if the user doesn't drag it.
- **Fix age is invisible at both ends.** The accuracy circle is honest about
  space, silent about time; a 29-minute-old static fix looks identical to a fresh
  one.
- **`decodeOffline` never checks the checksum** and is a public export — one
  obvious integrator call defeats the headline safety property.
- **Operational:** free web tier cold-starts 30–50s; the keep-warm cron doesn't
  run 00:00–05:59 UTC, so the first overnight caller waits ~40s. Free keyvalue is
  non-durable — a restart wipes live sessions (privacy-safe, availability-fatal).

## 1. Senior tech lead

**Verdict:** The engineering instincts are good and unusually honest — typed
discriminated-union phases, evidence-based connectivity, structural expiry done
properly, a miss-priced limiter that genuinely works in the authenticated mode.
The problem is a consistent **gap between the code and its own prose**: a
redaction that never ran, a `trustProxy` that inverts the limiter's foundation, a
"live" feature that is a banner over a fire-and-forget loop, and a checksum whose
"provable" framing is narrower than a reader assumes. Every one of those is the
same failure this project keeps catching itself on — a confident claim attached
to an unmeasured mechanism.

**Plan (in priority order):**
1. **Make the claims true or delete them.** Fix or remove the log redaction and
   stop logging raw codes; correct the README. Change `TRUST_PROXY` to one hop.
   Publish the *full* error-class table (substitution 100%, chunk-swap 50%, twins
   19%) — don't let "every single-character error" stand in for "robust".
2. **Fix the concept-level checksum weakness**, not just the docs. Either move to
   a transposition-complete scheme (Damm / ISO-7064 over 32) or make chunk-swap
   structurally impossible with asymmetric chunking (e.g. 3-5 display, not 4-4).
   This is a protocol change and should happen before any wider claim.
3. **Make "live" honest.** Track last-acked PATCH; after N seconds without one,
   flip the banner to "NOT updating since HH:MM", report unreachable, handle the
   `watchPosition` error. Add a mint timeout + automatic offline-code fallback
   (the fallback already exists; it's just unreachable from a hung fetch). Persist
   the active session to `sessionStorage`.
4. **Close the API sharp edges:** cap/authenticate mint and drop `MAX_TTL` from
   4h; make claim-on-read atomic (compare-and-set in Lua); rate-limit
   PATCH/DELETE; `decodeOffline` must verify checksum; add an offline-code format
   version + committed golden vectors.
5. **Field data before field claims.** `interpretCode` (the dispatcher entry
   point) has zero tests; there is zero human-transcription data anywhere. A small
   real read-aloud-over-phone-audio trial is the minimum before "every
   single-character error is caught" is said to anyone in a control room.

## 2. Marketer

**Verdict:** The positioning is already right and rare — it's disciplined about
what it is *not* ("anyone claiming to replace AML is selling something"), which is
exactly the credibility w3w lost. The wedge is genuine: **the fallback slot on a
voice call, and third-party / moving-casualty reporting** — the gaps AML
structurally cannot fill and where w3w has a public safety record (MREW's 2021
warning: 45 bad locations in 12 months from spelling/accent errors). The story
practically tells itself to the mountain-rescue / niche-responder audience,
because they already feel this pain and already push SMS-link tools (SARLOC /
PhoneFind) that are the true incumbent — not w3w.

**But** the marketing must not outrun the measured truth. "Provably catches every
error" is a hostage to the first pen-tester who finds the 50% chunk-swap number.
Lead with the *offline-code confusability* result (which is real and defensible)
and the fail-*closed* behaviour, not with an over-broad checksum claim.

**Plan:**
1. **Pick one audience: UK mountain / cave / lowland rescue.** They own the
   fallback-slot pain, they're a warm, reachable community (UKClimbing /
   UKHillwalking forums, MREW), and they're already comfortable with a
   browser-link workflow. Not "emergency services" in the abstract.
2. **Publish the comparison as a public page** — but rebuilt around the *honest*
   numbers: offline-code confusability (zero confusable neighbours, measured),
   fail-closed vs w3w/Plus Code fail-silent, and the chunk-swap caveat stated
   openly. Radical honesty is the brand here; it's what the incumbents lack.
3. **A 90-second demo film** of the third-party + moving-casualty flow (the two
   things AML and w3w both can't do). That's the whole pitch and it already
   works on a phone.
4. **Open-spec as the message.** "Audit the thing your responders depend on" is a
   direct, fair shot at w3w's litigious closed algorithm and a real
   differentiator for public-safety buyers.
5. **Rename away from "emergency".** Keep the neutral-tech-demo framing that
   cleared Safe Browsing; position as "location handover protocol", let the
   responder community supply the emergency context.

## 3. Tester

**Verdict:** Coverage is thin exactly where risk is highest. The codec has good
property tests but the dispatcher entry point (`interpretCode`) has none, the
whole web package has no tests, and every headline number lives in throwaway
scripts rather than CI. For a tool whose entire pitch is "measured, not
asserted", the measurements aren't reproducible from the repos.

**Plan:**
1. **Commit the measurement scripts and run them in CI.** The substitution
   sweep, the chunk-swap/twin/transposition table, the offline-confusability
   sweep, and the Plus Code experiment. Every quoted number becomes a test that
   fails if the property regresses. This is the single highest-value testing move
   and it's cheap — the scripts already exist.
2. **A human transcription trial.** 10–20 people, real phone audio (ideally a bad
   line), reading codes to a "dispatcher" typing them in. Measure the *actual*
   re-ask rate and error rate — including "zed"/"oh"/chunk-swap in the wild. This
   is the data that either validates or kills the voice-channel claim, and there
   is currently none of it.
3. **Adversarial/abuse suite against the API:** IP-spoof rate-limit bypass, mint
   flood → store exhaustion, claim-race (two resolvers, same code), 429 lockout
   blocking a legitimate dispatcher (the self-DoS I hit today).
4. **Web integration tests for the failure paths that matter:** mint timeout →
   offline fallback, live-update failure → banner truthfulness, reload →
   session survival, offline manual-pin on a blank map.
5. **A parser fuzz + strict mode:** enumerate the spoken forms a UK caller and an
   STT engine produce; decide per-form accept/reject deliberately; test that
   garbage never resolves to a confident location (currently 3.77% of
   right-length garbage passes the checksum silently).

## 4. CEO

**Verdict:** This is a strong, well-argued *artefact* and a genuine *idea*, and
it is nowhere near a *product* — and it doesn't need to be, yet. The honest
assessment: the concept has one defensible, measured advantage (fail-closed +
non-confusable offline codes), one real market gap (the fallback slot + third-
party/moving cases), and a mountain of adoption risk (zero installed base,
against SARLOC which responders already use for free). The value here is not a
company; it's **a spec and a demo that could influence how the fallback slot is
done** — or become a small, free, open, community-adopted tool.

**Plan (next steps, sequenced):**
1. **Decide the ambition honestly.** Three real options: (a) *portfolio /
   influence* — a beautifully-argued open spec + demo that shows what "fail-
   closed voice codes" should look like, cited by others; (b) *niche free tool*
   — get one mountain-rescue team using it in anger; (c) *venture* — not
   credible without field data and a distribution partner. Recommend (a)→(b);
   (c) is off the table until a real trial exists.
2. **Get it in front of one real responder team** (via the UK MR community /
   Geovation network). Their reaction to the third-party + moving-casualty demo
   is the only signal that matters. Everything else is theory.
3. **Enter Geovation** (Ordnance Survey's accelerator): £20k equity-free, OS/HMLR
   data + mentorship, and — crucially — the introductions to exactly the
   public-safety buyers this needs. Low cost, high signal, fits the "pay for
   itself" bar on its own.
4. **Before any of that, close the credibility gaps** the tech-lead plan lists —
   because the first thing a serious counterparty does is find the 50% chunk-swap
   number and the "live" banner that isn't. Ship truthful claims first.
5. **Set a kill/continue gate:** if the field trial shows the re-ask rate is no
   better than reading lat/long, stop — the whole thesis is that voice codes fail
   safer, and that's a measurable yes/no.

## 5. How it pays for itself

The bar was "cover its own costs", not "make money". **Current burn is
essentially £0** (Render free tier + Cloudflare free + GitHub Pages), so it
*already* pays for itself — the real question is what covers the ~£7–15/month a
*credible* deployment costs (paid always-on Render + durable keyvalue, needed the
moment cold-start/durability matter). Options, cheapest-effort first:

1. **Stay free-tier for demo, upgrade only for a real pilot** — and let the pilot
   partner (a rescue team, or Geovation) absorb the ~£15/mo. Most likely path.
2. **Geovation accelerator** — £20k equity-free covers years of hosting outright
   and adds distribution. Best cost/benefit by a wide margin.
3. **"Sponsor a resolver" / GitHub Sponsors** — an open-source public-safety tool
   with an honest story is exactly the kind of thing that attracts small
   recurring sponsorship; ~£15/mo is a very low bar.
4. **Open-spec + paid hosted resolver** (long-term, only if adoption comes): the
   protocol stays free and auditable; organisations that want an SLA'd, durable,
   audited resolver node pay for *that*. Mirrors w3w's "free to use, businesses
   pay" model but without the closed-algorithm problem. Note w3w did £2.1M revenue
   on £150M cumulative losses — a caution, not a template.

**Recommendation:** it pays for itself today; keep it that way until a real pilot
justifies the ~£15/mo, and let Geovation or the pilot partner carry that cost.
Don't build a business model before there's a single real user.

## 6. The aligned plan (where all four roles converge)

One sequence, in order. Each step is what makes the *next* one honest.

**Phase 1 — Make it tell the truth (tech lead + tester lead).**
- Fix/remove log redaction + stop logging raw codes; correct README.
- `TRUST_PROXY` → one hop; cap/authenticate mint; drop MAX_TTL.
- Make "live" honest (banner reflects last-acked update; mint timeout + fallback;
  persist session).
- Publish the full error-class table; `decodeOffline` verifies checksum.
- Commit every measurement script to CI.
_These are the credibility gate. Nothing outward-facing goes out before them._

**Phase 2 — Fix the concept weakness (tech lead).**
- Transposition-complete checksum or asymmetric chunking so chunk-swap can't
  pass. Strict parser mode that handles real UK spoken forms.

**Phase 3 — Get one real signal (tester + CEO).**
- Human transcription trial over phone audio (the measured yes/no on the whole
  thesis).
- One mountain-rescue team trying the third-party/moving-casualty demo.

**Phase 4 — Tell the story (marketer + CEO).**
- Honest public comparison page (lead with offline-confusability + fail-closed).
- 90-second demo film. Enter Geovation.

**Kill/continue gate after Phase 3:** if voice codes don't measurably lower the
re-ask/error rate vs lat/long, stop. If they do, that's the number the entire
pitch is built on — and then it's real.
